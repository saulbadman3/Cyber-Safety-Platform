# Ручні тест-кейси та security checklist

Тимчасові навчальні дані мають бути замінені командними матеріалами перед пілотом. Гроші вводяться у гривнях; у перевірках порівнюйте значення з точністю до копійки.

## Функціональні сценарії

| № | Передумови та дія | Очікуваний результат |
|---:|---|---|
| 1 | Відкрити титулку на ширині 360 px | Hero, CTA і меню не виходять за межі екрана |
| 2 | Перейти з титулки кнопкою «Пройти анкету» | Відкривається реєстрація з переходом до анкети після успіху |
| 3 | Зареєструвати нову адресу з паролем 10+ символів | Створено обліковий запис; відкривається профіль бізнесу |
| 4 | Увійти з чинними даними | Відкривається дашборд; сесія зберігається в HttpOnly cookie |
| 5 | Вийти та відкрити захищений маршрут напряму | Сесія очищена; користувача спрямовано на вхід |
| 6 | Створити профіль бізнесу і почати анкету | Чернетку створено; видно «Питання 1 з 14» та категорію |
| 7 | Відповісти й перейти вперед | Відповідь автозбережена; прогрес збільшився на одне питання |
| 8 | Перейти назад у середині анкети | Відкрилося попереднє питання з попередньою відповіддю |
| 9 | Оновити сторінку чернетки | Є пропозиція продовжити; позиція та відповіді відновилися з API |
| 10 | Обрати «Не знаю» | Видно повідомлення про прогалину у знаннях; відповідь збережена |
| 11 | Завершити 14 відповідей «Так» | Рейтинг 100; усі категорії мають 100; ризик низький |
| 12 | Завершити всі відповіді «Ні» | Рейтинг 0; слабкі зони впорядковані за зростанням бала |
| 13 | Зберегти значення калькулятора | Оцінка SLE/ALE перерахована і збережена для вибраного сценарію |
| 14 | Розгорнути пояснення сценарію збитку | Показані припущення й тимчасові джерела з seed-даних |
| 15 | Змінити статус дії на «В роботі» | Статус збережений і відображається після перезавантаження |
| 16 | Додати відповідального і строк дії | Значення збережені та надруковані у звіті |
| 17 | Відкрити мікроурок | Показаний текст, ключові висновки та пов’язані рекомендації |
| 18 | Пройти всі 12 карток вікторини | Пояснення після кожної відповіді; наприкінці показано бал |
| 19 | Відкрити звіт і скористатися друком | Український текст і всі секції доступні у print preview |
| 20 | Завершити другий аудит | Дашборд показує обидва рейтинги та порівняння |
| 21 | Встановити `PREMIUM_ENABLED=false` | Історія та PDF приховані/недоступні за feature flag |

## Межі та помилкові вводи

| № | Передумови та дія | Очікуваний результат |
|---:|---|---|
| 22 | Зареєструватися з некоректною адресою | Форма показує українське повідомлення валідації |
| 23 | Зареєструватися з паролем довжиною 9 | Запит не створює обліковий запис; показана вимога 10 символів |
| 24 | Повторити реєстрацію з тією самою адресою | Єдина помилка API; немає необробленої помилки сервера |
| 25 | Увійти з невірною адресою, потім з невірним паролем | Однаковий текст відповіді в обох випадках |
| 26 | Зробити більше 8 спроб входу за 15 хвилин | Спроби обмежені кодом 429; після вікна ліміт відновлюється |
| 27 | Відправити відповідь до неіснуючого питання | API повертає 422 у єдиному форматі помилки |
| 28 | Відправити відповідь з невідомим значенням | API повертає 422; стан чернетки не змінюється |
| 29 | Завершити анкету не відповівши на всі питання | API відхиляє запит; статус лишається `draft` |
| 30 | Зберегти `AV=-1` | Валідація відхиляє від’ємну вартість активу |
| 31 | Зберегти `EF=-0.01` або `EF=1.01` | Валідація відхиляє значення поза 0–1 |
| 32 | Зберегти `ARO=-0.1` | Валідація відхиляє від’ємну частоту |
| 33 | Зберегти `ARO=0` | ALE дорівнює 0 грн на рік |
| 34 | Задати ARO із багатьма десятковими знаками | Чітка валідація або коректне округлення Decimal без float-артефактів |
| 35 | Відкрити звіт для чернетки | Повідомлення про відсутній результат; сервер не створює результат |
| 36 | Відкрити вигаданий ID аудиту | Єдине повідомлення 404; приватні дані не показані |
| 37 | Задати порожній або завеликий `page_size` | API відхиляє параметр або обмежує його задокументованою межею |
| 38 | Відправити JSON із зайвими або помилковими типами полів | API повертає 422 уніфікованої форми |

## Security checklist

- [ ] Паролі зберігаються лише як Argon2id-хеші; у відповідях API немає хешу.
- [ ] Cookie сесії має HttpOnly, Secure у production і SameSite=Lax.
- [ ] Кожна мутація з cookie-сесією перевіряє CSRF cookie та заголовок.
- [ ] Власник перевіряється на кожному маршруті аудиту й пункту плану.
- [ ] Чужий ID не дає змоги відрізнити наявний об’єкт від відсутнього.
- [ ] Повідомлення про невдалий логін не розкриває наявність email.
- [ ] Ліміт спроб входу не можна обійти зміною регістру email.
- [ ] CORS відхиляє origin поза allowlist.
- [ ] CSP, `X-Content-Type-Options`, `X-Frame-Options` та `Referrer-Policy` присутні.
- [ ] Введений користувачем текст виводиться як текст; небезпечний HTML не інтерпретується.
- [ ] `JWT_SECRET` і паролі БД передаються лише через env/secrets; їх немає в Git і логах.
- [ ] SQL доступ здійснюється через SQLAlchemy ORM/параметризовані вирази.
- [ ] Залежності перевіряються `pip-audit` та `npm audit` у CI.
- [ ] Print-версія звіту не показує навігацію й елементи керування.
